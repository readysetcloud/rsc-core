How it works

Session, connect, stream

Four steps from a signed-in user to streamed tokens, with identity verified before any model call.

  1. Configure a session.A signed-in caller POST /agent/sessions (or backend code calls createSession()) with an optional system prompt, model, temperature, max tokens, title, named first-party tools, and external mcpServers. The row is pk=SESSION#{id}, sk=CONFIG, owned by the verified caller. This is the knob for behavior: the runtime is a generic host, so changing a prompt or a model is a data operation.
  2. Get the URL.The browser calls POST /agent/connect with the sessionId and receives the wss:// URL. On custom-domain deploys that is wss://chat.<domain>/ws, a CloudFront proxy that hides the account id in the runtime ARN.
  3. Stream.The browser opens the socket presenting its Cognito ID token as an OAuth bearer in the Sec-WebSocket-Protocol header. The runtime’s inbound JWT authorizer validates it, the runtime reads the verified sub, loads the session config, refuses a mismatch with the owner, builds the assistant, and streams stream_event then complete frames.
  4. Remember.Conversation snapshots persist per session; AgentCore Memory extracts long-term facts and preferences per user and injects them on later turns.
Sessions

Dynamic configuration

One deployed host serves many differently-behaved agents. Everything about a session is data.

FieldTypeMeaning
systemPromptstringThe persona and instructions. Defaults to the package prompt.
modelIdstringBedrock model id (cross-region profile prefix included). Defaults to the deploy’s chat model.
temperature, maxTokensnumberSampling controls; package defaults when unset.
titlestringDisplay name for the conversation.
toolsstring[]Names from the host’s first-party tool registry to enable for this session.
mcpServersrecordExternal MCP servers by label: url, headers, optional authHeader. Hosts must be allowlisted.
userIdstringSet by the host from the verified caller. The session’s owner; never client-supplied.

Create a session from a backend

The verified user becomes the owner. The host enforces ownership at connect time.

import { createSession, getSessionConfig } from '@readysetcloud/agent/memory';

const { sessionId } = await createSession({
  userId,                                   // verified caller — the OWNER
  systemPrompt: 'You are a terse code reviewer.',
  modelId: 'us.anthropic.claude-sonnet-4-...',
  tools: ['http_request'],
});

// At connect, the host loads it and refuses a mismatch:
const config = await getSessionConfig(sessionId);
if (config && config.userId !== verifiedSub) throw new Error('not your session');
createSession is conditional on the session not already existing, so an owner can never be overwritten. A session with no config row runs with package defaults. The generated id is a UUID, which satisfies AgentCore’s session-id length requirement.
Frontend

Rendering chat in an app

The app owns auth and injects a URL getter; the chat components never import app auth.

@readysetcloud/ui/chat

Create the session once, then return the URL plus the bearer subprotocol on every (re)connect.

import { Chat } from '@readysetcloud/ui/chat';
import { useAuth } from '@readysetcloud/ui/auth';

const { user, getToken } = useAuth();
const authed = async (path, body) =>
  (await fetch(`${CORE_API_URL}${path}`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${await getToken()}`, 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  })).json();

// base64url without padding — how AgentCore expects the bearer in the subprotocol.
const b64url = (s) => btoa(s).replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');

// 1. Create a session once (optionally set prompt/model), keep the id in state.
const { sessionId } = await authed('/agent/sessions', { systemPrompt, modelId });

// 2. Per (re)connect, return the URL + the Cognito ID token as an OAuth bearer subprotocol.
const getConnectionUrl = async (sid?: string) => {
  const { wsUrl } = await authed('/agent/connect', { sessionId: sid });
  const token = await getToken();
  return {
    url: wsUrl,
    protocols: [`base64UrlBearerAuthorization.${b64url(token)}`, 'base64UrlBearerAuthorization'],
  };
};

// 3. Render.
<Chat sessionId={sessionId} userId={user.sub} getConnectionUrl={getConnectionUrl} title="Assistant" />;

Wire protocol

What travels over the socket

Server to browser

A turn is a series of stream_event frames, then one complete. Errors close the turn.

{ "type": "stream_event", "event": { "init_event_loop": true } }
{ "type": "stream_event", "event": { "data": "Here" } }
{ "type": "stream_event", "event": { "current_tool_use": { "name": "http_request", "tool_use_id": "..." } } }
{ "type": "stream_event", "event": { "data": " is what I found." } }
{ "type": "stream_event", "event": { "complete": true } }
{ "type": "complete", "session_id": "..." }
{ "type": "error", "error": "...", "message": "..." }
// Browser to server: one request per turn. user_id is optional; the
// runtime prefers the verified id from the connection.
{ "request": "What shipped this week?", "session_id": "..." }
A rejected token closes the socket with code 4401 or 1008; the UI client surfaces both as an auth error rather than a reconnect loop.
Memory

Two planes of memory

Continuity within a conversation and recall across them are different problems with different stores.

Conversation snapshots

Within and across a connection. Strands snapshots persist to the agent table at pk=SESSION#{sessionId} with a 30-day TTL, so a reconnect resumes exactly. Available to chat and to tasks tied to a session.

Cross-session memory

Across sessions, per person. The chat runtime hands each turn to AgentCore Memory; it extracts facts (/facts/{sub}) and preferences (/users/{sub}/preferences) scoped to the verified caller, and the Strands memory manager injects the relevant ones each turn, plus a search_memory tool for explicit lookups.

Tasks run memory-light by default: snapshots only, no AgentCore Memory, so the task Lambda does not carry that dependency. A host that needs long-term recall in a task passes a memoryManager to createAssistant.
