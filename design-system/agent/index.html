@readysetcloud/agent

The shared AI agent behind Ready, Set, Cloud: a Strands-TS core that streams chat to the browser, runs autonomous tasks from an API or an event, and, with the agency primitives, behaves like something that has a job to do.

These pages document the rsc-core agent service and the npm package behind it, @readysetcloud/agent. The package builds four agent types. Three run on the shared service, which every Ready, Set, Cloud app uses from one deployment and reconfigures with data (a session row, an event) rather than a redeploy. The fourth, the persistent agent, is a build tool: your app defines it and runs it in its own stack.
What it is

One agent core, four agent types

Chat, tasks, and one-shot runs are services you call. A persistent agent is something you build and run yourself.

Streaming chat

A browser opens a WebSocket to the AgentCore runtime with its Cognito token as the bearer and streams tokens back through @readysetcloud/ui/chat. Per-user, cross-session memory included.

Read →

Autonomous tasks

A one-shot "do something" run with no socket: triggered by POST /agent/tasks or a Run Agent Task event, idempotent under at-least-once delivery, result delivered inline or on the bus.

Read →

Server-side one-shot

runAgent builds an agent, runs one turn, and returns a schema-validated object. No table, no trace. For orchestrators fanning one input across several analyses.

Read →

Persistent agents · build tool

Define an agent type once with definePersistentAgent and deploy its router and task handler in your own stack. Each instance has a persona, is woken by your events and its own check-ins, paces itself, and keeps goals and promises across runs. Not hosted by the shared service.

Architecture

How a request moves

Identity is verified at the edge, behavior is loaded from data, and results leave as events.

Chat path

Browser → POST /agent/connect → wss://chat.<domain> → AgentCore Runtime (NODE_22) → stream frames back. The runtime loads the session config, enforces that the verified caller owns it, and builds the assistant.

Task path

API or event → RunAgentTaskFunction (Lambda) → conditional claim on the task row → build agent → run → Agent Task Completed event. Duplicate deliveries never re-run the agent.

Use cases

What people build with it

Patterns already in use across the ecosystem, and the pieces they are made of.

In-app assistant

A support or research chat inside a dashboard. Chat + a session with the app’s system prompt + an MCP server scoped to the user’s own data via authHeader.

Content review engine

Fan a draft across grammar, fact-check, and style lenses, each a runAgent with its own model and schema, then synthesize. Run the outer call as a task for idempotency.

Nightly digest

A schedule emits Run Agent Task as a system principal; the result event fans out to email or Slack. No user, no socket.

Workflow step

A Step Functions state or a Lambda calls POST /agent/tasks with wait: true and gets a structured answer inline in under ~25 seconds, or a ticket plus an event.

Persistent persona

An agent that reviews what it is assigned, pursues open goals across runs, keeps the promises it makes in chat, and checks in three times a day, built with definePersistentAgent and run in the app’s own stack. The fantasy-league AI managers are this.

Ecosystem automation

Any first-party stack with events:PutEvents can request a run and react to its completion without touching the agent’s table or IAM.

Quick start

Four ways in

Pick the agent type that matches the job.

Install

Published on npm as @readysetcloud/agent. Node 22+. Import ./memory or ./agency from Lambdas that should not bundle the Strands runtime.

npm install @readysetcloud/agent
import { runAgent, createAssistant, runAgentTask } from '@readysetcloud/agent';  // the runtime
import { requestAgentTask, createSession } from '@readysetcloud/agent/memory';   // Strands-free data plane
import { routeTrigger, reconcileAgenda } from '@readysetcloud/agent/agency';     // Strands-free agency

Backend: trigger a task

Fire-and-forget from any first-party Lambda. Only events:PutEvents is needed.

import { requestAgentTask } from '@readysetcloud/agent/memory';

const { taskId } = await requestAgentTask({
  principal: { type: 'system', id: 'newsletter' },
  request: 'Summarize this week’s new blog comments as three bullets.',
});
// Listen for "Agent Task Completed" with this taskId.
# Or over the API as the signed-in caller (waits up to ~25s for the result)
curl -X POST "$CORE_API_URL/agent/tasks" \
  -H "Authorization: Bearer $ID_TOKEN" -H "Content-Type: application/json" \
  -d '{"request":"Summarize this week’s new blog comments.","wait":true}'

Frontend: render chat

Create a session, then hand the chat component a function that returns the socket URL and the bearer subprotocol.

import { Chat } from '@readysetcloud/ui/chat';
const { sessionId } = await authed('/agent/sessions', { systemPrompt });
<Chat sessionId={sessionId} userId={user.sub} getConnectionUrl={getConnectionUrl} title="Assistant" />

Library: run one turn

No table, no session. Build, run, validate, return.

import { runAgent } from '@readysetcloud/agent';
import { z } from 'zod';

const { output } = await runAgent({
  input: draft,
  systemPrompt: 'You are a grammar and spelling reviewer.',
  outputSchema: z.object({ suggestions: z.array(z.object({ span: z.string(), fix: z.string() })) }),
});

Build tool: define a persistent agent

One definition gives you the router and the task handler to deploy in your stack. See Agency → Define one.

import { definePersistentAgent } from '@readysetcloud/agent/agency';

export const reviewer = definePersistentAgent({
  name: 'reviewer',
  profile: (agentId) => loadReviewer(agentId),          // persona + pacing, or null
  rules: { 'Pull Request Opened': { kind: 'review', agents: ({ detail }) => detail.reviewers, request: ({ detail }) => `Review #${detail.pr}` } },
  checkIn: { agents: () => listReviewerIds() },
  tasks: { review: (ctx) => review(ctx), check_in: (ctx) => followUp(ctx) },
  observe: async (ctx) => ({ needs: await openReviewRequests(ctx.agentId) }),
});

export const route = (event) => reviewer.route(event);            // your router Lambda
export const task = (event) => reviewer.handleTask(event.detail); // your task Lambda
