Persistent agents

An agent with a job to do

The primitives that make an agent feel like it has agency: it is woken by what concerns it, paces itself like a person, pursues durable goals, keeps the promises it makes, and checks in on its own.

Everything on this page is the @readysetcloud/agent/agency subpath. It is Strands-free, so a Lambda imports it without bundling the runtime, and every piece composes with the task path: a trigger becomes a Run Agent Task, and the task reads its agenda and commitments on the way in and reconciles them on the way out. The design was extracted from the AI managers in ai-fantasy-league.
Why

What makes an agent feel like it has agency

A task that runs when asked is a function. An agent people believe in does five more things.

It is woken by what concerns it

Not every event. A rule per event type names the agents it touches and the kind of work it calls for.

It paces itself like a person

A cooldown so it is not woken twice for the same work, and a seeded, right-skewed delay so it does not answer the instant something lands.

It keeps pursuing a goal

A typed agenda reconciled from what the host observes, never from what the model claims. A goal stays open until it is really done.

It keeps its promises

“I’ll look into that” becomes a record with an explicit lifecycle, owned by one task at a time, settled by results rather than words.

It shows up on its own

A scheduled check-in a few times a day where “nothing to do” is a fine, model-free answer.

It never changes its mind on a replay

Every roll is seeded by event and agent, so a redelivered event lands on the same task id with the same delay.

Shape

How the pieces fit

None of them requires the others. Together they make the loop below.

Your eventsand a scheduled check-in
→
routeTriggerrules, gates, delay
→
Run Agent Task+ trigger, or Schedule Event
→
Your task runnerreads agenda, runs
→
Observe + reconcileupdateAgentState
→
Follow-upsback through the router
  1. Route.Your event consumer calls routeTrigger with your rules. For each agent a rule concerns it takes the agent’s cooldown slot (a conditional write), computes a delay, and dispatches a Run Agent Task with a deterministic taskId and a trigger { kind, eventId, detailType, payload }. A delayed task is handed to Schedule Event named by its task id.
  2. Run.Your Run Agent Task consumer reads detail.trigger.kind to pick the task’s behavior, loads the agenda, puts agendaLines(...) in the prompt, and runs. Deterministic code decides what the agent may do; the agenda only orders the options.
  3. Reconcile.After acting, the task observes the real state again and reconcileAgendas it under updateAgentState. A goal completes only when the observation stops reporting the need; a pending request is not a result.
  4. Commit.When a conversation produces a promise, openCommitment records it by reference and the task dispatches a follow-up that owns it. The follow-up reports back through advanceCommitment, and a check-in picks up lost or reconsiderable ones.
  5. Check in.A cron emits an event carrying checkInMoment(now); a oncePer rule keyed by date and slot routes a check_in to every agent with a routine delay, so each wanders in at its own time.
Triggers

Rules, gates, and delays

The router is a table of rules. Each rule answers: who, what kind of task, how urgently, and how often.

Rule fieldMeaning
kindThe task kind requested; also the agent’s default cooldown slot, so a review never delays a reply.
agents(detail)Which agents the event concerns. Empty routes nowhere.
request(input), payload(input)The instruction the task runs and the ids it needs. Never the event’s untrusted text.
urgentBypasses cooldowns and delays (a deadline) but still starts the cooldown.
oncePer(detail)Fire once per key across every delivery and every event with that key (a daily window keyed by date).
cooldownA named slot and window instead of the agent’s baseline, shared by kinds that should pace together (every chat kind).
sharedCooldownOne reaction per moment across all agents the rule reaches.
admit(input)A per-agent gate before the cooldown: a personality roll, a budget check. Returns a reason or null.
delay(input)Milliseconds to wait. humanDelay(profile, { deadline }) builds the usual one.
GateSlotSemantics
Once-per keyrule#{kind}#{key}Taken once, forever (windowMs: null). A redelivery of the same event passes again because it is the owner.
Shared cooldownrule#{kind}#shared#{key}Last taken at least ms ago, or the owner’s.
Agent cooldown{agentId}#{kind or slot}As above with the agent’s baseline window; urgent sets the window to 0 and always passes.
Every gate is an owner-checked conditional write (dynamoTriggerGates in production, memoryTriggerGates in tests). Two deliveries racing for one gate cannot both pass, while a retry of the same event passes its own gates again and lands on the same task id, where runAgentTask’s claim makes it a no-op.

Response delays

A right-skewed sample sized by the kind of event, scaled by the agent’s temperament, capped, and clamped to a share of the time left before a deadline.

import { responseDelay, RESPONSE_DELAY_PROFILES } from '@readysetcloud/agent/agency';

// Profiles: prompt (seconds), conversational (minutes), considered (~45m, cap 8h), routine (~90m, cap 12h)
const { delayMs, reason } = responseDelay({
  profile: 'considered',
  seed: `${eventId}:${agentId}`,                      // same seed, same delay
  lever: { multiplier: 1, immediateChance: 0.1 },     // part of the persona; { 0, 1 } answers at once
  now,
  deadline: offer.expiresAt,                          // never past half the time left
});
Agenda

Goals reconciled from observation

A model’s summary is lossy and has no completion condition. An agenda does.

RuleEffect
Observed, not claimedNeeds come from a fresh authoritative read the host performs. The model never completes a goal.
IdempotentThe same need reported again creates nothing. The same id in the same epoch keeps its createdAt.
Stable orderingA still-open goal keeps its place ahead of newly discovered needs, so the agent does not thrash between priorities.
Stale reads rejectedAn observation older than the last, or from an earlier epoch, changes nothing.
CompletionA need that stops being reported completes its goal. A new epoch expires the old epoch’s goals. closed cancels them all.
BoundedAGENDA_LIMITS: three active goals, twelve in history, or your own.

Reconcile after acting

Read the real state, reconcile under the revision-checked store, and project active goals into the next prompt.

import { readAgentState, updateAgentState, reconcileAgenda, agendaLines, emptyAgenda, type Agenda } from '@readysetcloud/agent/agency';

type Need = { repo: string; pr: number; reason: 'requested' | 'stale' };

// Before the run: into the prompt.
const agenda = (await readAgentState<Agenda<Need>>({ agentId, name: 'agenda' }))?.value ?? emptyAgenda<Need>();
const lines = agendaLines(agenda, (g) => `Review ${g.data.repo}#${g.data.pr} (${g.data.reason})`);

// After the run: observe, then reconcile.
const open = await listOpenReviewRequests(agentId);        // an authoritative read
await updateAgentState<Agenda<Need>>({
  agentId, name: 'agenda',
  update: (current) => reconcileAgenda(current ?? emptyAgenda<Need>(), {
    at: new Date().toISOString(), taskId,
    needs: open.map((r) => ({ id: `review:${r.repo}#${r.pr}`, kind: 'review', data: r })),
  }),
});
Do
const rank = agendaPriority(agenda, (g) => serves(option, g));
const pick = legalOptions.sort((a, b) => rank(b) - rank(a))[0];

Priority orders options that already passed legality, budget, and permission checks.

Don't
if (agendaPriority(agenda, ...) > 0) overpay(option);

A goal is never permission to overpay, skip a check, or act outside the agent’s authority.

Commitments

Promises with a lifecycle

What was asked, where, which task owes the work, what it decided and why, and whether that was reported back.

queuedopened
→
evaluatingstart
→
waiting_on_counterpartwaiting + externalRef
→
fulfilled · declined · cancelled · expiredsettle
TransitionWho may apply itEffect
openCommitmentThe task that heard the promiseIdempotent per source; duplicate for the same intent still open with that counterpart; limit when the agent already owes enough (three open, one per counterpart).
startThe assigned task onlyqueued → evaluating
waitingThe assigned task onlyRecords the external thing it produced (an offer id, a ticket) and waits on the counterpart.
closedThe assigned task onlyA final reason and the facts it rested on. reconsider: true schedules one more look after a cooldown, if the deadline allows.
settleA read of the system of recordWhat the counterpart did. Never from chat.
redispatchA check-inresume a queued look whose task never started; reconsider a due decline when materialChange finds something new. Bounded by child tasks and reconsiderations.

Record a promise, then dispatch the task that owns it

The text is never stored. The follow-up re-reads the message by reference.

import { updateAgentState, openCommitment, emptyCommitments, taskIdFor, type CommitmentBook } from '@readysetcloud/agent/agency';

const followUpId = taskIdFor(`promise:${msg.id}`, agentId, 'investigate');
let outcome;
await updateAgentState<CommitmentBook<{ test: string }>>({
  agentId, name: 'commitments',
  update: (book) => {
    const r = openCommitment(book ?? emptyCommitments(), {
      kind: 'investigate', at: now, taskId: followUpId,
      counterpart: msg.from, source: { channel: msg.channel, ref: msg.id, visibility: 'shared' },
      intent: { test: 'flaky-login-spec' }, expiresAt: twoDaysFromNow,
    });
    outcome = r.outcome;
    return r.book;
  },
});
if (outcome === 'created') await dispatchFollowUp(followUpId, agentId);
// 'existing' (a redelivery) and 'duplicate' dispatch nothing; 'limit' means say so instead of promising.
Check-ins

The heartbeat

Fixed wall-clock times in the agent’s own time zone. A late or retried job still counts as that check-in.

Compute the moment, emit it, route it once

The default schedule is morning, afternoon, and evening, US Eastern.

import { checkInMoment } from '@readysetcloud/agent/agency';

// In the scheduled job (an EventBridge rule on a cron):
const moment = checkInMoment(new Date(), { timeZone: 'America/New_York', slots: { morning: 9, afternoon: 14, evening: 20 } });
await publish('Agent Check-In', { date: moment.date, slot: moment.slot, nextAt: moment.nextAt.toISOString() });

// In the rules:
'Agent Check-In': {
  kind: 'check_in',
  agents: () => listAgents(),
  oncePer: (d) => `${d.date}-${d.slot}`,
  delay: humanDelay('routine', { deadline: (d) => d.nextAt }),
  request: () => 'Look over your open goals and anything you said you would do.',
}
Worked example

A reviewer agent, end to end

Rules, pacing, dispatch, and the task that reads its agenda.

rules.ts

What wakes the agent and how it paces itself.

import { routeTrigger, humanDelay, dynamoTriggerGates, eventBridgeDispatcher, type TriggerRuleMap, type TriggerRouterDeps } from '@readysetcloud/agent/agency';

type PrOpened = { repo: string; pr: number; reviewers: string[]; dueAt: string };

const rules: TriggerRuleMap = {
  'Pull Request Opened': {
    kind: 'review',
    agents: ({ detail }: { detail: PrOpened }) => detail.reviewers,
    delay: humanDelay<PrOpened>('considered', { deadline: (d) => d.dueAt }),
    request: ({ detail }) => `Review pull request #${detail.pr} in ${detail.repo}.`,
    payload: ({ detail }) => ({ repo: detail.repo, pr: detail.pr }),
  },
  'Review Deadline Near': {
    kind: 'review',
    urgent: true,
    agents: ({ detail }: { detail: PrOpened }) => detail.reviewers,
    request: ({ detail }) => `Finish your review of #${detail.pr} now.`,
  },
};

const deps: TriggerRouterDeps = {
  rules,
  gates: dynamoTriggerGates({ prefix: 'reviewers' }),
  pacing: async (agentId) => {
    const persona = await getPersona(agentId);
    if (!persona) return null;                                 // not one of ours: skipped
    return { cooldownMs: 15 * 60_000, responseDelay: persona.responseDelay };
  },
  principal: (agentId) => ({ type: 'system', id: agentId }),
  dispatch: eventBridgeDispatcher({ sessionId: (t) => `reviewer-${t.agentId}` }),
  responseDelays: process.env.RESPONSE_DELAYS !== 'off',
};

export const handler = (event) => routeTrigger(deps, event);
DecisionMeaning
requestedDispatched (now, or scheduled by delayMs). Carries the taskId.
cooldownThe agent’s slot for this kind is still warm.
repeatThe once-per key was already taken by another event.
shared_cooldownAnother agent already reacted to this moment.
declinedThe rule’s admit turned the agent away; reason says why.
unknown_agentpacing() returned null: not an agent this router runs.
Boundaries

Guarantees, and what is deliberately left out

GuaranteeWhere it comes from
Observed, not claimedAgenda and commitment transitions take authoritative reads and task results; a model’s words never complete or settle anything.
Idempotent under at-least-once deliveryOwner-checked gates, deterministic task ids, idempotent openCommitment, stale-observation rejection, compare-and-swap state writes.
BoundedActive goals, open commitments per agent and per counterpart, history, child tasks, reconsiderations.
Private by constructionA commitment stores where something was said, never the text. Whether agenda lines reach a prompt that can post publicly is your call.
Not included (yet): the fantasy league’s durable dispatch outbox with recovery sweep, per-task budget admission, and a kill switch. Here a failed dispatch throws to the router and EventBridge retries the consumer; the gate stays the task’s own so the retry passes. Spend control is the host’s.
